# خادم MCP لسنوي

يربط سنوي بكلود. بدل فتح الشاشة لتسجيل إيداع أو معرفة القسط، تسأل بلغتك
ويقرأ كلود من حسابك ويكتب فيه:

> «حطّيت 500 على تأمين السيارة» → يسجَّل الإيداع ويردّ بالرصيد والقسط الجديد
> «كيف وضعي هذا الشهر؟» → الدخل والالتزامات والباقي للصرف
> «أي شهر جاي بيكون ثقيل؟» → تقويم الاثني عشر شهراً وأثقلها
> «كم تكلّفني السيارة فعلاً؟» → التأمين والטסט والטיפול والبنزين مقسومةً على 12

يعمل بنقلين: **رابط بعيد** لتطبيق كلود على التلفون، و**stdio** لعميل يشغّله على
جهاز. المنطق واحد — الفرق نقلٌ لا أدوات.

---

## أ. الرابط البعيد — لكل مستخدمي سنوي

خادمٌ واحد على Supabase يخدم الجميع. الرابط **ليس سرّاً**: كلود يفتح به صفحة
دخول سنوي، وكل مستخدم يدخل بحسابه فيرى بياناته هو وحده.

**١. أسرار المستودع** — GitHub ← Settings ← Secrets and variables ← Actions:

| السرّ | من أين |
|---|---|
| `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens |
| `SUPABASE_PROJECT_REF` | معرّف مشروع سنوي |
| `VITE_SUPABASE_URL` · `VITE_SUPABASE_ANON_KEY` | Supabase ← Settings ← API |
| `SANAWI_TOKEN_SECRET` | **ولّده أنت**: نصّ عشوائي ٣٢ حرفاً فأكثر. به تُشفَّر رموز كل المستخدمين |

لا بريد ولا كلمة سرّ: الخادم لا يعرف حساباً بعينه، وكلٌّ يدخل بنفسه.

**٢. النشر** — يقع تلقائياً مع كل دمج على `main`، بعد نجاح `ci.yml`.
وللنشر اليدوي — بعد تبديل سرّ، أو لرفع الخادم في وضع القراءة فقط:
Actions ← «نشر خادم MCP» ← Run workflow.

**٣. الربط** — claude.ai ← Settings ← Connectors ← Add custom connector:

```
https://<PROJECT_REF>.supabase.co/functions/v1/sanawi-mcp
```

يفتح كلود صفحة دخول سنوي، المستخدم يكتب بريده وكلمة سرّه، ويعود بأدواته.

## كيف يعمل الدخول

كلود لا يعرف مستخدمي سنوي، وسنوي لا يعرف كلود. OAuth هو اللغة بينهما:

1. كلود يطلب الأدوات بلا رمز → يردّ الخادم `401` ومعه عنوان خادم التفويض.
2. كلود يسجّل نفسه (Dynamic Client Registration) ويفتح `/authorize`.
3. الخادم يتحقّق من العميل ورابط عودته، ثم **يحوّل إلى صفحة الدخول على نطاق
   التطبيق** (`connect.html`) — لا في محادثة ولا عند كلود.
4. الصفحة تبادل كلمة السرّ بجلسة **عند Supabase مباشرةً**، ثم تعيد الجلسة
   وحدها إلى الخادم، فيتحقّق منها ويصدر رمزاً مربوطاً بـ PKCE.
5. كل نداء بعدها يحمل رمز ذلك المستخدم، فتنطبق **سياسات RLS على صاحبه وحده**.

**لماذا الصفحة على نطاق التطبيق؟** لأن Supabase يحوّل أي `text/html` تردّه
دالّة إلى `text/plain` عمداً — قيدُ منصّة موثَّق، وليس عطلاً يُصلَح. والنقل
مكسبٌ لا تنازل: المستخدم يسجّل دخوله على النطاق الذي يعرفه، و**كلمة السرّ لا
تمرّ بخادمنا أصلاً** — فلا يملك ما يخزّنه حتى لو أراد.

ولا جدولَ رموز في القاعدة: كل رمز يحمل محتواه مشفَّراً بـ `SANAWI_TOKEN_SECRET`
(AES-GCM، ولكلِّ نوعِ رمزٍ غرضٌ يدخل بصمته). تبديل السرّ يُلغي رموز الجميع —
وهو أسلوب الإلغاء الوحيد المتاح، ويناسب حجم التطبيق.

## ب. stdio — على جهاز

### التنصيب

```bash
npm install
npm run build:mcp
npm run check:mcp   # تجربة كاملة بلا حساب — انظر «التجربة» أدناه
```

ثم سجّله عند كلود. من سطر الأوامر:

```bash
claude mcp add sanawi \
  --env SANAWI_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co \
  --env SANAWI_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_KEY \
  --env SANAWI_EMAIL=you@example.com \
  --env SANAWI_PASSWORD=... \
  -- node /absolute/path/to/Sanawi/mcp/dist/mcp/index.js
```

أو في `claude_desktop_config.json` لتطبيق كلود على سطح المكتب:

```json
{
  "mcpServers": {
    "sanawi": {
      "command": "node",
      "args": ["/absolute/path/to/Sanawi/mcp/dist/mcp/index.js"],
      "env": {
        "SANAWI_SUPABASE_URL": "https://YOUR_PROJECT_REF.supabase.co",
        "SANAWI_SUPABASE_ANON_KEY": "YOUR_PUBLISHABLE_KEY",
        "SANAWI_EMAIL": "you@example.com",
        "SANAWI_PASSWORD": "..."
      }
    }
  }
}
```

المسار يجب أن يكون مطلقاً: العميل يشغّل العملية من مجلد غير معروف.

## الإعدادات

| المتغيّر | لازم | ماذا يفعل |
|---|---|---|
| `SANAWI_SUPABASE_URL` | ✔ | رابط المشروع. بديله `VITE_SUPABASE_URL` |
| `SANAWI_SUPABASE_ANON_KEY` | ✔ | المفتاح العام. بديله `VITE_SUPABASE_ANON_KEY` |
| `SANAWI_EMAIL` · `SANAWI_PASSWORD` | لـ stdio | حساب واحد. لا يلزمان في وضع OAuth |
| `SANAWI_READ_ONLY` | — | `1` يجعل أدوات الكتابة غير مسجّلة أصلاً |
| `SANAWI_TOKEN_SECRET` | للرابط البعيد | سرّ تشفير رموز OAuth، ٣٢ حرفاً فأكثر |
| `SANAWI_PUBLIC_URL` | — | العنوان العام المعلن. يضبطه التدفّق تلقائياً؛ اضبطه يدوياً خلف وكيلٍ آخر |
| `SANAWI_LOGIN_URL` | — | صفحة الدخول على نطاق التطبيق. الافتراضي `sanawi.kabblan.com/connect.html` |
| `SANAWI_MCP_TOKEN` | — | مفتاح ثابت لوضعٍ شخصي بحسابٍ واحد على الرابط. بديلٌ لـ OAuth لا مكمّل |

الأدوات تقبل **اسم** الالتزام أو المجموعة كما ينطقه المستخدم، لا معرّفه فقط.
وإن طابق الاسمُ أكثر من واحد تُردّ قائمة المرشّحين ولا يُخمَّن: الإيداع في
الصندوق الخطأ خطأ صامت لا يُكتشف إلا بعد شهور.

`sanawi_group_cost` يعمل بالتصنيف (`car` و`health` و`events` و`home` و`lifestyle`
و`other`) أو بمجموعة صريحة. التصنيف هو الوضع المعتاد لأنه ما تكتبه الواجهة فعلاً؛
جدول `obligation_groups` موجود في السكيما ولا تكتب فيه أي شاشة بعد.

### مصادر الدخل

المصادر متعدّدة بطبيعتها: راتبٌ يُقبض شهرياً أو أسبوعياً، وشغلٌ جانبي دخله
متغيّر. و`is_variable` تعني «لا تقدير له»: يبقى المصدر ظاهراً ويدخل في **ما
وصل** عبر `sanawi_record_income`، ولا يدخل في **المتوقَّع** — لأن اختراع رقمٍ
ثابت له يضخّم الدخل ويجعل «الباقي للصرف» وعداً لا يفي به الشهر.

و`sanawi_month_overview` يخرج `expected_income` و`received_income` و
`income_by_source` معاً. اذكرهما معاً دائماً: من يقبض أسبوعياً يسجّل أسبوعاً
في الثالث من الشهر، فيقرأ الواصلَ وحده وكأنه دخل الشهر كلّه.

وسمِّ المصادر بأسماء لا يحوي أحدها الآخر: المطابقة بالاسم تأخذ التطابق التامّ
أولاً ثم الجزئي، وعند الالتباس تسأل ولا تخمّن.

### الحسابات والمظاريف

**المال يعيش في الحسابات، والصناديق مظاريف فوقه لا بجانبه.** صندوق الالتزام
ليس مالاً — هو تخصيصٌ على مالٍ موجودٍ في حساب، فلا يُجمع الاثنان: من سجّل رصيده
البنكي وسجّل صناديقه كان صافي ثروته يخرج ضعفَ الحقيقة.

```
حساب الالتزامات        الرصيد الفعلي ₪2,000
  ├─ مظروف: تأمين السيارة        ₪2,000
  └─ غير مخصّص                       ₪0
```

و**غير المخصّص** (`available`) هو أهمّ رقمٍ تردّه `sanawi_list_accounts`: موجباً
أو صفراً فالوضع مضبوط، وسالباً (`shortfall`) فالتطبيق يَعِد بمالٍ ليس في البنك.

| | التحويل | الإيداع في صندوق |
|---|---|---|
| ما هو | نقل مال حقيقي بين حسابين | تخصيص مال **موجود أصلاً** |
| يغيّر أرصدة الحسابات | ✅ | ❌ |
| يغيّر المخصَّص | ❌ | ✅ |
| يغيّر صافي الثروة | ❌ | ❌ |

ومن يقول «حوّلت 2,000 للتأمين» يقصد الاثنين معاً، فـ`sanawi_add_deposit` تقبل
`from_account` وتكتبهما في نداءٍ واحد.

**الرصيد يُدخَل يدوياً** — لا ربط API ولا استيراد حركات — و`balance_is_stale`
تقول متى صار عمره أكثر من أسبوعين، فلا يُحسب عليه صامتاً.

**والدفع من حسابٍ غير حساب الصندوق يُقبل ويُعلَّم:** `sanawi_mark_paid` تنقص
رصيد `paid_from_account` بما خرج فعلاً، وتُنشئ تسويةً معلّقة تقول «حساب الصندوق
مدين للحساب الذي دفع» — يغلقها `sanawi_transfer_between_accounts` تلقائياً.
رفضُ الدفعة كان سيجبر المستخدم على الكذب.

**والصندوق غير المربوط حالةٌ انتقالية:** `sanawi_net_worth` تحتسبه ملكاً كما كان
قبل الحسابات لئلّا يهبط الرقم كذباً، وترفع `has_unlinked_funds` — عندها اقترح
ربطه بـ`sanawi_update_obligation`.

### الأقساط

بندٌ بتاريخ نهاية هو قسط، وبلا تاريخ هو متكرّر إلى الأبد. والفرق ليس تسمية:
القسط يخرج من الحمل الشهري حين ينتهي، ولوحة الشهر تقول متى ينخفض وبكم.

#### متى تبدأ الدفعات

بندٌ بلا `starts_on` دفعاته بدأت، وبتاريخٍ في المستقبل لم تبدأ بعد — فيظهر في
القوائم ولا يُحمَّل على شهرٍ لا دفعة فيه.

الحقل وُلد من خطأ حقيقي: رخصة سيارة بـ1,900 على ثلاث دفعات أولها 15/9 سُجّلت
في 5/8 فقيل «بقيت 4 دفعة — مجموعها 2,532». وسببه أن `ends_on` وحده يفترض أن
الدفعة الأولى في الشهر الحالي. و«اشتريت اليوم والدفع يبدأ الشهر الجاي» ليس
حالةً نادرة، هو النمط الشائع في الأقساط.

ويُتحقَّق من `total_amount` حين يُمرَّر مع عدد الدفعات: `القسط × العدد` يجب أن
يقارب المبلغ الكلّي، والتفاوت **تحذيرٌ في الرد لا استثناء** — القرض بفائدة
يجعل مجموع الأقساط أكبر من أصل الدَّين بحقّ.

#### العدد والتاريخ

والمستخدم ينطق **عدداً** — «مقسّطها على اثنا عشر» — والقاعدة تحفظ **تاريخاً**.
التحويل يقع عند الكتابة مرّة، ثم يُشتقّ العدد من التاريخ في كل قراءة: تخزين
الاثنين معاً يفتح باب تناقضهما بعد شهر، لأن العدد ينقص مع الزمن والتاريخ لا.

والعدّ يشمل دفعة هذا الشهر: «بقيت دفعة واحدة» تعني ادفع الآن وانتهيت. الفرق
بينها وبين صفر هو الفرق بين «ادفع» و«خلصت»، وهو أسوأ خطأ ممكن هنا — ولذلك له
فحصٌ يثبّت حدّه.

## التجربة

`npm run check:mcp` يشغّل تجربة كاملة **بلا حساب ولا شبكة**: يرفع Supabase مزيّفاً
في الذاكرة (`scripts/fake-supabase.mjs`)، ويمرّ على الأدوات كلها قراءةً
وكتابةً، ويقارن ما تردّه بأرقام محسوبة يدوياً — القسط والدورة المضغوطة وتحويل
الدخل الأسبوعي وتسوية الشركاء والتجديد بعد الدفع. لا يمسّ بياناتك: القاعدة
المزيّفة تموت مع العملية.

ويغطّي دورة OAuth كاملة: الاكتشاف، والتسجيل الديناميكي، وصفحة الدخول، وPKCE،
والتجديد — ثم **العزل**: مستخدمان يدخلان، ويتحقّق أن الثاني لا يرى صفّ الأول
ولا حتى عملته. القاعدة المزيّفة تحاكي RLS فعلاً، وإلا كان فحص العزل مسرحية.

ومع `SANAWI_EMAIL` و`SANAWI_PASSWORD` في `.env` يضيف نداءَ قراءةٍ واحداً على
حسابك الحقيقي للتأكّد من الاتصال والمفاتيح.

## القرارات

**لا مفتاح خدمة — في أي وضع.** كل جلسة تأتي من دخولٍ حقيقي: المستخدم يكتب
بريده وكلمة سرّه فتُستبدل بجلسة، ثم تُمرَّر في ترويسة كل استعلام. فتبقى سياسات
RLS هي الحارس نفسه الذي يحرس التطبيق، ولا يرى أحدٌ صفّاً لغيره. مفتاح الخدمة
يتجاوز السياسات كلها، وخادمٌ بصلاحية مطلقة على بيانات مالية يُسلَّم لنموذج لغوي
هو بالضبط ما لا نريده.

وهذا ما استبعد البدائل: تخزينُ رمز تجديد جلسة التطبيق يُخرج المستخدم من تلفونه
عند أول تدوير، وتخزينُ كلمة السرّ مشفّرة أسوأ من مفتاح خدمة، وانتحالُ المستخدم
بمفتاح إداري يلغي المعنى كلّه. الدخول الحقيقي وحده يعطي جلسةً مستقلة بلا شيء
من ذلك.

**الحساب من مصدر واحد.** الأقساط والتقويم والتجديد تُستورد من
`src/lib/obligations` و`src/lib/budget` — نفس الملفات التي تغذّي الشاشات.
القسط الذي يقوله كلود هو الرقم المعروض في تلفونك لأنه خارج من الدالة نفسها،
لا من نسخة ثانية تنحرف بعد أول تعديل. لهذا يبني `tsconfig.mcp.json` من جذر
المستودع، والمخرجات في `mcp/dist/mcp/index.js`.

**لا حذف.** الالتزام يُؤرشف، والصندوق يُفرَّغ بقيدٍ سالب لا بحذف الإيداعات.
تاريخ من دفع ماذا لا يُمحى بنداء أداة.

**النقل يتفرّع، والمنطق لا.** `mcp/server.ts` يبني الأدوات مرة واحدة،
و`index.ts` يوصلها بـ stdio و`http.ts` بـ fetch. ونقلُ HTTP مكتوب على
`Request`/`Response` القياسيين لا على أنواع Node، فيعمل كما هو في Deno —
وهذا وحده ما جعل النشر على Supabase ممكناً بلا نسخة ثانية من الخادم.
والدالّة تُولَّد من نفس المصدر بـ `npm run build:edge` عند النشر، ولا تُحفظ في
المستودع: ملفٌّ مولَّد محفوظ يبدو مصدراً ويُعدَّل بالخطأ.

**وضع القراءة يخفي الأدوات ولا يمنعها فقط.** مع `SANAWI_READ_ONLY=1` لا
تُسجَّل أدوات الكتابة أصلاً، فلا يمكن استدعاؤها. أداةٌ مسجّلة تردّ «ممنوع»
تبقى بابًا يُطرَق. و`npm run check:mcp` يتحقّق من ذلك في كل مرة.

## ملاحظة أمنية

**في الرابط البعيد:** كلمة السرّ لا تمرّ بالخادم أصلاً — تذهب من المتصفّح إلى
Supabase مباشرةً، ولا يصل الخادمَ إلا أثرُها: جلسةٌ يتحقّق منها. فلا يملك ما
يخزّنه حتى لو أراد، ولا يمرّ منها شيء إلى كلود ولا إلى المحادثة. ولا مفتاحَ خدمة: الدخول حقيقيٌّ لا انتحال، فتبقى RLS الحارس الوحيد
على البيانات.

يبقى `SANAWI_TOKEN_SECRET` هو ما يستحقّ الحراسة: من يملكه يستطيع صناعة رموز
لأي مستخدم. عامله كما تعامل مفتاح قاعدة بيانات.

**في stdio:** كلمة السر تعيش في إعداد عميل MCP على جهازك بنصّ صريح — كحال كل
خوادم MCP المحلية. من يفتح جهازك يقرأها.

في الحالتين: شغّله بـ `SANAWI_READ_ONLY=1` إن أردت حدّاً أدنى من المخاطرة،
وبدّل `SANAWI_MCP_TOKEN` فوراً إن شككت أن الرابط تسرّب.
